# Domain Documents

## Glossary

Use one root `CONTEXT.md` unless bounded contexts genuinely require a map. Define project-specific meaning in one or two sentences, optionally with discouraged synonyms; exclude implementation instructions and requirements.

## Architectural Decisions

Record only costly, non-obvious choices among real alternatives. Keep context, decision, and rationale; follow repository numbering. Supersede rather than rewrite meaningful history.

## Placement

Follow existing placement. Otherwise prefer root `CONTEXT.md` and `docs/adr/`, created only with a real entry.
