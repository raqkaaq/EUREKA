# UI Prototype

Generate three structurally distinct variants by default and never more than five. Variants must disagree about layout, information hierarchy, or primary interaction—not merely color or wording.

Prefer embedding variants in the real surrounding page so authentic navigation, density, data, and constraints remain visible. Use a new prototype route only when no meaningful host exists. Keep data reads realistic but direct mutations to a stub or disposable environment.

Make variants switchable through a stable URL or simple control, with the current option clearly identified. After a choice, record why it won, implement the selected design under production standards, and keep losing variants out of the production path.
