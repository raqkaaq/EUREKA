# Pull Requests

Read base, head, linked issues, commits, diff, comments, reviews, checks, mergeability, and draft state.

A PR draft states:

- problem and outcome;
- issue and closure links;
- key decisions or scope deviations;
- checks run and skipped;
- risks, migrations, breaking behavior, and required citations;
- remaining work while draft.

Use a title for the whole change, not the commit list. Verify every field after creation or update.

Publish review findings only when authorized. Preserve their evidence, severity, and separation between specification and standards. Track resolved, disputed, and remaining findings distinctly.

Before merging, verify approvals, checks, conversations, issue links, notes, and merge strategy. Merge only when authorized, then verify resulting history, branch state, issue closure, and follow-ups. Stop before bypassing protections, forcing, or rewriting history.
