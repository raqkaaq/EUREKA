# Issues

Read the full issue and its relationships. Use repository templates and labels.

Before creating or editing:

1. Search for duplicates, existing behavior, and prior rejection.
2. Capture one outcome, current/desired behavior, acceptance criteria, exclusions, and blockers.
3. Prefer stable behavior over implementation detail.
4. Preview graphs or consequential transitions.
5. Create blockers before dependants; wire and verify native relationships.

Ready work needs a brief a fresh agent can execute. Map triage's semantic states to repository labels.

For `map-work`, the parent indexes decisions; children own detail. The frontier is open, unblocked, unclaimed children. Claim first, resolve on the child, then link a gist from the map. Leave unformulated uncertainty as fog.

Do not publish exploratory discussion, rewrite parent issues, or close work without authorization.
